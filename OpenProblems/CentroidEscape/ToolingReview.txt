Generator proof coverage
------------------------
Each leaf proves all60 square/next-coefficient recurrence identities with
decide+kernel. CompactStageAssembly merely combines these proofs; it does
not replace any arithmetic identity by a premise or a native result.
Both endpointCorrect (the actual degree60 Horner endpoint) and input and
endpoint canonical-margin checks are actual kernel computations.

Every internal block glue compares the complete seven-coordinate endpoint
and next input vector. The segment theorem uses the coefficient0 lemma
and the actual endpoint theorem. A terminal table with only coefficient0
is sufficient because no further stage is asserted there.

The shard's local stage0 corresponds to global START. Original JSON step
numbers are checked against the requested global indices before emission.
Balanced merges use the left count n and right count m, append at n,
preserve the left initial vector and right terminal vector, and prove the
boundary coefficient0 equality from the endpoint/input vector equality.
Odd carried blocks retain their own count. No off-by-one error was found.

Partial schema: old full status defaults to start0 and mesh_steps750;
new partial status gives start and number of written steps. The requested
interval must be covered. In both cases h=L/750 is checked. Note that the
native partial status.initial field is the GLOBAL starting seed, not the
state at START. The generator correctly obtains shard first_input from
records[0].coefficients[0], not from that status.initial field.

No analytic ODE error is inflated or restarted inside shards. The data
prove a segment of the exact polynomial iteration. The complete path
assembly must still check its initial point and use the global analytic
error theorem; a partial segment is not a completed shooting certificate.

Compiler findings and fixes
--------------------------
1. Generated dependencies previously could resolve to an earlier LEAN_PATH
   entry while a different artifact had just been produced in build-root.
   The final code rejects such shadowing and requires each generated import
   hash to equal this run's already successful producer result.
2. A preflight exception previously occurred before clearing an old success
   report. This was reproduced with an isolated source-hash mismatch:
   exit1 but an old shard_kernel_checked=true remained. The fixed version
   atomically clears success before preflight and the top-level exception
   handler records failed/false. The same negative test now passes.
3. A fresh compile previously could find a stale named output after exit0.
   The fixed code compiles to a unique, initially nonexistent temporary
   olean. Only exit0 plus a new nonempty artifact can replace the official
   output. The audit also requires its success marker.
4. On Linux, terminating only the /usr/bin/time wrapper could leave its
   Lean child running. The final code creates a new session and terminates
   the process group on abort.

The new resume path reuses a module only when source, direct-import hashes,
output hash and Lean version agree. Generated dependencies additionally
must match this run's producer results, including reused producers.
The final Audit is always freshly compiled, never reused from a JSON bit.
Nonzero exits, missing dependencies, exceptions, absent/empty artifacts,
unresolved dependency cycles, and missing audit markers cannot produce
a final true status in the reviewed control flow.
