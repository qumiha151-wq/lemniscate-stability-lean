The two previous issues are resolved at source level:

1. Tool/workflow commit separation:
checked_tool_revision executes actual local Git queries from the publisher's
own directory. It clears inherited GIT_* variables, reads the real worktree
top and HEAD, checks the file lies inside that checkout, and compares the
committed HEAD:path blob byte-for-byte with the executing publisher source.
actions_context requires this actual tool revision to equal the separately
pinned request publisher revision P. The real GITHUB_SHA is independently
validated and recorded as workflow revision Q with run/event identity; it is
not overwritten or falsely relabelled as P. Rechecks before later mutations
and final success reject a moved checkout. Adapter helper hashes remain
separately tied to the externally pinned request. This permits tool commit P
to precede the later request/workflow commit Q without a self-hash cycle.

The unit fixture mocks Git process responses and checks arguments, env cleanup,
correct revision, and wrong committed blob rejection. It does not claim an
actual separate P/Q checkout deployment; that remains a workflow check.

2. Durable journal primitives:
The publisher now owns durable_new rather than changing the frozen core helper.
Every event, raw REST response and result.json is created exclusively, flushed,
file-fsynced, then followed by a directory fsync on POSIX. durable_directory
creates missing directories from the first existing ancestor outward and
syncs each new directory's parent entry and the new directory itself.
Consequently mutation_intent returns only after these operations, before the
HTTP request is sent; failures are propagated. No destructive cleanup or retry
was introduced. The started event records the actual platform's sync mode and
explicitly disclaims survival of loss of the whole runner.

This matches the local-storage distinction in Linux man-pages fsync(2):
https://man7.org/linux/man-pages/man2/fsync.2.html .
The author test ran on Windows, where directory fsync is skipped and explicitly
reported as not exercised; no power-loss test or Linux durable-storage test is
claimed. This is a source-level correction with accurate execution limits.
