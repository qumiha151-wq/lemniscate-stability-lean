The reader binds exact request, plan, catalog, implementation and helper
bytes before doing work. Production validation retains the exact successful
whole remaining-246 run requirement. The caller cannot supply a selected
artifact list as a substitute for the catalog. The outer source itself is
checked against the actual committed tool blob in the same checkout as the
already-reviewed v3 publisher and its helpers. P/Q Actions identity checks
remain unchanged. Fixtures cannot yield production receipts.

The metadata client is read-only, with no retry, wait or cleanup. The
complete O0 catalog observation precedes the quota gate. This gate consumes
the most recent observation from this same client and context; it requires
N+2A+100 remaining primary requests. It neither reserves quota atomically
nor claims to rule out secondary limits. One complete original Actions ZIP
is requested by artifact ID for each requested shard. An approved redirect
is followed without Authorization. Every ZIP is streamed to a fresh file
with an exact byte cap, complete SHA256 and a total deadline. A complete O1
catalog observation must agree with O0 after the transfers.

The archive extraction checks central-directory names, duplicate/casefold
names, explicit parent file/directory conflicts, encryption, special file
types and expanded-size/member-count caps. It extracts only the exact
canonical shard archive member. That member's CRC, byte count and raw
archive SHA are checked. Other ZIP members are not read or CRC checked;
only their directory metadata is examined. All original ZIP bytes are
nevertheless covered by the complete ZIP SHA. The outer receipt is not a
substitute for the publisher's unchanged full raw-archive preflight.

The disk gate accounts for remaining ZIPs and archives, the frozen 512 MiB
single-preflight stage cap, and 2 GiB headroom. It is rechecked before each
transfer. Completion checks the journal hash chain, saved raw API response
hashes, pinned inputs/helpers and exact output inventory, then rehashes all
files listed in the checked receipt. Extra files or directories do not
silently become part of the receipt.
